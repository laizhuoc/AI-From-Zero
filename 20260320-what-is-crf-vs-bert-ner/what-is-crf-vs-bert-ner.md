# CRF和BERT做命名实体识别有什么区别？如何选择合适的方法？

> by @Laizhuocheng

---

## 一、简介

想象一下你正在开发一个智能客服系统，需要从用户输入中自动识别"姓名"、"手机号"、"产品名"等关键信息。2015年的时候，你可能用的是基于**特征模板+条件随机场（CRF）**的方法；到了2020年，你大概率会直接调用BERT等预训练模型。

为什么技术路线会发生这样的转变？是因为CRF不够好吗？还是BERT真的全面碾压？

**答案是：两种方法各有千秋，选择取决于你的具体场景**。

如果你做的是简历解析，每份简历格式都差不多，实体类型固定（学校、公司、专业），用特征工程+CRF可能效果不错且成本低。但如果你处理的是社交媒体文本，用户可能用"绝绝子"、"yyds"这种网络用语，还经常有错别字和缩写，这时候BERT的优势就体现出来了。

**命名实体识别（NER）的本质差异**：CRF代表的是基于规则和特征工程的传统方法，强调人工设计特征和概率建模；BERT代表的是基于预训练和深度学习的现代方法，强调从海量文本中自动学习语言规律。这两种方法的差异，本质上是NLP领域对"如何让机器理解语言"这个根本问题的认知升级。

## 二、什么是CRF和BERT两种NER方法？

### 基于特征工程+CRF的NER

**CRF**（Conditional Random Field，条件随机场）是一种概率图模型，特别适合处理序列标注问题。它的核心思想是：**当前位置的标签不仅受当前输入影响，还受前后标签的影响**。

举个例子："张三是工程师"这句话，用BIO标注法应该是：
- "张" → B-PER（人名开头）
- "三" → I-PER（人名内部）
- "是" → O（其他）
- "工" → B-JOB（职业开头）
- "程" → I-JOB（职业内部）
- "师" → I-JOB（职业内部）

**关键组成部分**：
1. **人工特征设计**：当前字是否是常见姓氏？前后是否有特定称谓？这个字前后2个字的窗口内容是什么？
2. **线性链结构**：每个位置的标签只依赖于相邻标签
3. **转移矩阵**：学习标签之间的约束规则（如B-PER后面大概率是I-PER）

**优点**：
- 特征表达清晰，容易解释
- 训练和推理速度快，CPU就能跑
- 在特定领域效果不错（如果特征设计得好）

**缺点**：
- 需要大量人工特征工程
- 对新词、新表达适应性差
- 迁移成本高（换个领域要重做特征）

### 基于BERT的NER

**BERT**（Bidirectional Encoder Representations from Transformers）代表了一种完全不同的思路：**让模型从海量文本中自动学习语言规律，而不是靠人工告诉它**。

BERT在预训练阶段已经见过无数包含"张三"这种人名的句子，它通过掩码语言模型和下一句预测任务，逐渐学会了在向量空间里把人名、地名、机构名这些概念区分开。

**关键技术是自注意力机制**，每个字的表示都能关注到句子中所有其他字。所以"张三是工程师"这句话里，"张"字的向量表示会融合"三"、"工程师"这些上下文信息；而"张家界是景点"里的"张"字向量会完全不同，因为它周围的上下文变了。

**优点**：
- 无需人工特征工程，自动学习语义表示
- 对新词、新表达适应性强
- 预训练带来的知识迁移，小样本也能效果不错
- 能捕获长距离依赖（传统方法很难做到）

**缺点**：
- 计算成本高，需要GPU支持
- 模型黑盒，可解释性差
- 训练和推理速度慢

## 三、两种方法如何工作

### CRF的工作流程

```
输入文本: "张三是工程师"
    ↓
特征提取 (人工设计的特征模板)
    ├─ 姓氏特征: "张"在姓氏表中 → +0.8
    ├─ 窗口特征: 前1字是B-PER → +0.6
    ├─ 词性特征: "是"的词性是动词 → -0.3
    └─ ...
    ↓
特征向量: [0.8, 0.6, -0.3, ...]
    ↓
线性链CRF (学习标签转移概率)
    ├─ P(B-PER | "张") = 0.9
    ├─ P(I-PER | "三", 前一个是B-PER) = 0.85
    ├─ P(O | "是", 前一个是I-PER) = 0.7
    └─ ...
    ↓
输出标签序列: B-PER I-PER O B-JOB I-JOB I-JOB
```

CRF最关键的部分是**标签转移矩阵**，它学习标签之间的约束规则。比如：
- B-PER后面大概率是I-PER（人名通常不止一个字）
- B-PER后面不太可能是I-ORG（不能从人名跳到机构名）
- O后面可能是任何标签的开头（其他词后面可以开始任何实体）

这种约束让CRF很少出现违反BIO规则的输出，比如I-PER作为实体开头这种错误。

### BERT的工作流程

```
输入文本: "张三是工程师"
    ↓
BERT编码器 (预训练好的深层神经网络)
    ├─ 输入层: [CLS] 张 三 是 工 程 师 [SEP]
    ├─ 注意力层: 每个字关注所有其他字
    │   └─ "张"的关注重点: "三"、"是"、"工程师"...
    └─ 输出层: [vector_张, vector_三, vector_是, ...]
    ↓
分类层 (简单全连接层或+CRF)
    ├─ vector_张 → 分类器 → 概率: B-PER 0.9, O 0.08, B-LOC 0.02
    ├─ vector_三 → 分类器 → 概率: I-PER 0.85, O 0.1, B-ORG 0.05
    └─ ...
    ↓
输出标签序列: B-PER I-PER O B-JOB I-JOB I-JOB
```

BERT的核心优势在于**双向上下文建模**。传统方法只能看当前字前后几个字（比如前2后2的窗口），但BERT让每个字都能直接访问整个句子的信息。

比如在"公司创始人张三毕业于清华大学"这句话里，标注"清华大学"时：
- **传统方法**：主要看"清华"、"大学"这几个字和它们的特征，很难利用到前面"创始人"这个远距离的上下文
- **BERT**："清华大学"的向量表示天然就融合了"公司"、"创始人"、"毕业于"这些关键上下文

### 为什么BERT+CRF成为了主流？

虽然BERT本身已经很强大，但很多项目还是会在BERT后面加一层**CRF做后处理**。这种组合架构结合了两者的优势：

| 组件 | 职责 | 优势 |
|------|------|------|
| **BERT** | 语义编码 | 学习深层语义表示，捕获全局上下文 |
| **CRF** | 标签约束 | 保证标签序列合法，符合BIO规则 |

**为什么BERT自己不直接输出合法序列？**

因为BERT本质上是个编码器，它输出的是每个token的向量表示。如果直接在这些向量上做分类得到标签，每个位置的预测是**独立的**，可能出现违反BIO规则的情况。

CRF的强项恰好是建模标签间的转移约束，所以把BERT当作特征提取器，在它的输出上接一层CRF做解码，就能结合两者的优势。**关键点在于这不是简单的后处理，而是通过联合训练，让BERT的输出学会配合CRF的解码过程**。

实践中，BERT+CRF相比纯BERT分类，在F1值上通常能提升**1-2个百分点**。

## 四、CRF和BERT两种方法的优缺点

| 优势 | 劣势 |
|------|------|
| **CRF特征表达清晰**：每个特征的贡献明确，容易调试和优化 | **CRF需要大量人工特征**：领域知识要求高，开发周期长 |
| **CRF计算效率高**：训练和推理都在秒级，适合资源受限场景 | **CRF上下文范围有限**：只能看局部窗口，难以处理长距离依赖 |
| **BERT自动学习语义**：无需人工设计，能发现隐含的语言规律 | **BERT计算成本高**：需要GPU支持，推理延迟较高 |
| **BERT适应性强**：对新词、网络用语、错别字处理能力强 | **BERT黑盒性强**：难以解释为什么这么标注，调试困难 |
| **BERT知识迁移好**：预训练带来的先验知识，小样本也能有效果 | **BERT过拟合风险**：容易记住标注噪声，对数据质量敏感 |
| **BERT+CRF效果最佳**：结合两者优势，F1值通常能提升1-2个百分点 | **BERT+CRF训练复杂**：需要调两个模型的超参数，训练时间更长 |

## 五、实际应用场景与发展趋势

### 实际应用场景

#### 1. 简历解析系统（适合用CRF）

**场景**：招聘平台从简历中提取"学校"、"专业"、"公司"、"职位"等信息。

**为什么用CRF**：
1. 简历格式相对固定，实体边界容易定义
2. 可以构建领域词典：学校名单、公司名单、职位词表
3. 部署在客户内网，无GPU资源
4. 对推理速度要求高（每秒处理上百份简历）

**实施策略**：
- 人工设计特征模板（是否在已知大学列表中、前后是否有时间分隔符）
- 使用通用中文词性标注器获取词性特征
- 用领域词典增强特征（学校、公司、职位词表）
- 线上服务每条简历处理时间 < 50毫秒

**效果**：
- **准确率**：85%以上
- **响应时间**：<50毫秒
- **部署成本**：低（无需GPU）

#### 2. 社交媒体情感分析（适合用BERT）

**场景**：电商平台从微博、知乎评论中提取"产品名"、"属性"、"情感词"。

**为什么用BERT**：
1. 文本多样：有口语化表达、网络用语、错别字
2. 实体表达灵活："iPhone 14 Pro"、"苹果14"、"苹果十四"都是同一种产品
3. 新产品不断上市，模型需要快速适应
4. 可用云服务器，有GPU资源

**实施策略**：
- 使用中文BERT预训练模型（如`bert-base-chinese`）
- 微调阶段准备5000条标注数据
- 输出层用全连接分类，不加CRF（实体边界容忍度高）
- 线上服务平均响应时间 200毫秒

**效果**：
- **准确率**：90%以上
- **响应时间**：200毫秒
- **适应性**：能处理网络用语和错别字

#### 3. 医疗文本信息抽取（适合用BERT+CRF）

**场景**：医院从电子病历中提取"疾病"、"药品"、"症状"、"检查项目"等信息。

**为什么用BERT+CRF**：
1. 医学术语专业，需要深度语义理解
2. 嵌套实体多："急性心肌梗死"中"急性"是修饰词，"心肌梗死"是疾病
3. 边界准确性要求高（影响后续诊疗决策）
4. 资金充足，愿意投入计算资源追求效果

**实施策略**：
- 使用医疗领域预训练模型（如`medbert`）
- BERT输出接线性层+CRF，保证标签序列合法性
- 单独处理嵌套实体（用多层标注或span-based方法）
- 训练时为CRF层设置更高的学习率（如`bert_lr=2e-5, crf_lr=1e-3`）

**效果**：
- **准确率**：疾病实体识别F1值达到92%
- **边界精度**：实体边界准确率95%以上
- **可靠性**：错误率低于1%

#### 4. 金融合同解析（适合用特征工程+BERT）

**场景**：从金融合同中提取"签约方"、"金额"、"期限"、"违约责任"等信息。

**特点**：
- 格式规范但术语专业
- 需要精确抽取数字和日期
- 对准确性要求极高

**混合策略**：
- 用正则表达式抽取数字、日期等结构化信息
- 用BERT处理语义部分（责任条款、义务描述）
- 用规则校验抽取结果的一致性

**效果**：
- **金额抽取准确率**：99%以上
- **条款识别准确率**：90%以上
- **综合效果**：显著优于纯规则或纯BERT方法

### 当前挑战

**计算成本问题**：

BERT base有110M参数，推理需要GPU。对于资源受限的场景（如移动端、边缘设备），需要考虑模型蒸馏（DistilBERT、TinyBERT）、量化、剪枝等优化策略。

**标注数据稀缺**：

很多垂直领域缺乏标注数据。解决方案包括：
- 半监督学习：用未标注数据辅助训练
- 远程监督：用规则生成弱标注数据
- 小样本学习：用提示工程在少量标注数据上微调

**嵌套实体识别**：

传统序列标注只能识别非嵌套实体。解决方案包括：
- Span-based方法：把每个可能的片段作为候选
- 基于图的方法：用图神经网络建模嵌套结构
- 多层标注：用多层BIO标签表示嵌套

**跨语言迁移**：

多语言BERT能解决部分问题，但小语种效果差。需要跨语言对齐、零样本学习等技术。

### 发展与演进

**技术演进脉络**：

```
特征工程 + 最大熵模型 (2001年前后)
    ↓
特征工程 + CRF (经典方案，沿用近15年)
    ↓
BiLSTM + CRF (用神经网络学特征表示)
    ↓
BERT + (CRF) (预训练范式，无需特征工程)
    ↓
BERT + Prompt + 少样本学习 (用大模型+提示词)
```

**新兴技术方向**：

1. **基于生成式的方法**
   - 不把NER当成序列标注，而是序列生成
   - 用大模型直接生成"{实体: '张三', 类型: '人名'}"这样的结构化输出
   - 优势：少样本学习能力强，能识别传统方法没见过的实体类型

2. **基于Prompt的方法**
   - 把NER任务转化为"完形填空"问题
   - 例子："张三的工作是工程师。" → "[MASK]是工程师。[MASK]是职位。"
   - 优势：利用预训练模型的原有能力，微调数据需求更少

3. **多任务联合学习**
   - 同时训练命名实体识别、关系抽取、事件抽取等任务
   - 优势：不同任务相互促进，提升整体效果

4. **持续学习与增量学习**
   - 模型上线后，遇到新实体类型不需要重新训练
   - 优势：适应业务变化，降低运维成本

## 六、总结与思考

基于特征工程+CRF的NER和基于BERT的NER，代表了NLP领域两种不同的思维方式：前者认为语言是有规则的，我们要把规则教给机器；后者认为语言的规则太复杂，不如让机器自己从数据中学。这两种思路各有适用场景，不是简单的谁替代谁，而是根据具体需求选择合适的方法或混合使用。

**总结**：NER技术的选择没有银弹，只有权衡。理解每种方法的本质和适用边界，比盲目追求最先进技术更重要。在实际项目中，往往需要结合多种方法——用简单的规则解决80%的问题，再用复杂的模型处理剩下的20%——这才是工程师的思维方式。

**思考**：技术的进步不是简单的新方法替代旧方法，而是在原有方法的基础上不断积累和融合。从特征工程到深度学习，从规则到数据，我们看到的是人类对语言理解方式的不断深化。真正的智能不在于掌握最复杂的技术，而在于理解技术的本质，并在合适的场景下做出明智的选择。这种从"知其然"到"知其所以然"的跨越，才是技术工作者最宝贵的财富。
