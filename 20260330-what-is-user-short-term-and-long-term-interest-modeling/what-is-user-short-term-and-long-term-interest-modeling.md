## 一、简介

想象这样一个场景：你平时喜欢看科技评测视频，这是你的长期爱好。但某天你突然对露营产生了兴趣，连续看了几个露营装备的视频。这时候，推荐系统应该怎么给你推荐内容？

如果只推荐露营视频，可能过几天你兴趣转移了，系统还在推露营，你会觉得"这推荐真不准"。但如果继续只推科技视频，又会错过你当下的真实需求。

这就是推荐系统面临的核心挑战：**如何同时捕捉用户当下的即时兴趣（短期兴趣）和稳定的长期偏好（长期兴趣）**。理解这两者的区别和建模方法，是构建一个"懂你"的推荐系统的关键。

---

## 二、什么是用户短期兴趣和长期兴趣建模

用户兴趣建模，简单来说就是让机器理解"用户喜欢什么"。但人的兴趣其实是分层的：

**短期兴趣**反映的是用户当前的即时需求，就像你突然想吃火锅，或者临时需要买一个生日礼物。这类兴趣来得快、去得也快，通常只持续几分钟到几天。

**长期兴趣**代表的是用户稳定的偏好，比如你一直喜欢科幻小说、热爱篮球运动。这类兴趣形成时间长，变化缓慢，可能持续数月甚至数年。

两者的本质区别在于**时间尺度和稳定性**。如果用同一套方法去建模，要么推荐结果太"飘"（被一次误点击带偏），要么太"死板"（用户明明在探索新领域，系统还在推老内容）。

## 三、短期兴趣和长期兴趣如何建模

### 3.1 短期兴趣建模：捕捉当下的意图

短期兴趣的核心特征是**连贯性**和**会话性**。用户在一个时间窗口内的行为往往不是孤立的，而是有明确的目标导向。

举个例子：在电商场景，用户点击了一个登山包，接着看冲锋衣、帐篷、登山杖——这个序列明显指向"户外露营"这个即时意图。

**建模方法：**

1. **行为序列编码**：取用户最近 N 条行为（比如最近 20 次点击），将每个 item 转换成 embedding 向量，排成一个序列。

2. **序列模型选择**：
   - 早期常用 GRU 或 LSTM
   - 现在更多使用 Transformer 变体，因为它能更好地捕捉长距离依赖
   - 高并发场景下，可能会选择更轻量的模型，或者用蒸馏技术压缩大模型

3. **时间衰减机制**：越近的行为权重越高。常用指数衰减函数：`exp(-λΔt)`，其中 Δt 是时间差，λ 是衰减系数。

```java
// 时间衰减权重计算示例
public double calculateTimeDecay(long currentTime, long actionTime, double lambda) {
    long deltaTime = currentTime - actionTime;
    double deltaHours = deltaTime / (1000.0 * 3600);
    return Math.exp(-lambda * deltaHours);
}
```

4. **注意力机制（DIN 模型）**：用候选 item 去查询用户的历史行为序列，动态计算每个历史 item 的相关性权重。这种"看什么激活什么"的机制，天然契合短期兴趣的易变性。

### 3.2 长期兴趣建模：挖掘稳定的偏好

长期兴趣建模要解决的是**"从噪声中提取稳定信号"**的问题。用户几个月的行为数据里，有真实偏好，也有误点、朋友代操作、节日临时需求等噪声。

**建模方法：**

1. **统计聚合**：统计用户在各个品类的点击占比、购买频次、平均停留时长等指标，转化成特征向量。

2. **多兴趣网络**：一个用户往往有多个长期兴趣。比如 YouTube 的多兴趣网络，用聚类方法把用户历史行为 embedding 聚成 K 个簇（比如 K=5），每个簇代表一个独立的兴趣点。

3. **时间窗口选择**：长期兴趣通常使用 30 天到 90 天前的数据，排除最近的短期波动，让模型学习稳定模式。

4. **离线预计算**：长期兴趣向量通常是离线计算好的，存储在 Redis 等 KV 存储中，推荐时直接查询，保证实时性。

### 3.3 融合策略：让两者协同工作

单独使用短期或长期兴趣都有局限，实际应用中需要融合两者。

**召回阶段**：
- 用长期兴趣向量检索相似 item 库
- 用短期序列做实时的协同过滤
- 两路召回结果合并后再进入排序阶段

**排序阶段**：
- **拼接法（Concat）**：将短期特征和长期特征拼接后输入深度模型
- **门控机制（Gate）**：设计一个小型神经网络，根据用户上下文（时段、场景）动态调节两者权重

```java
// Gate 机制动态融合示例
public float[] fuseInterests(float[] shortTermInterest, 
                              float[] longTermInterest,
                              String scenario) {
    double gateValue = 0.5;
    
    // 搜索场景更依赖短期兴趣
    if ("search".equals(scenario)) {
        gateValue = 0.7;
    } else if ("browse".equals(scenario)) {
        gateValue = 0.3;
    }
    
    float[] result = new float[shortTermInterest.length];
    for (int i = 0; i < result.length; i++) {
        result[i] = (float)(gateValue * shortTermInterest[i] + 
                           (1 - gateValue) * longTermInterest[i]);
    }
    return result;
}
```

## 四、两种建模方式的优缺点

| 维度 | 短期兴趣建模 | 长期兴趣建模 |
|------|-------------|-------------|
| **优势** | 能及时响应用户当下需求；捕捉探索性兴趣；避免推荐过于固化 | 提供稳定的推荐基线；抗噪声能力强；适合冷启动后的持续推荐 |
| **劣势** | 容易受误点击干扰；可能过度敏感；需要实时计算，性能压力大 | 更新滞后；难以捕捉兴趣迁移；可能陷入"信息茧房" |
| **适用场景** | 搜索场景、实时推荐、用户活跃期 | 首页推荐、沉默用户唤醒、品类偏好预测 |
| **计算方式** | 在线实时计算 | 离线预计算 |
| **更新频率** | 每次交互后更新 | 按天或按周批量更新 |

## 五、实际应用与发展趋势

### 5.1 实际应用场景

**电商推荐**：
- 短期兴趣用于捕捉用户的即时购物意图（比如临时搜索"生日礼物"）
- 长期兴趣用于维护用户的品牌偏好、价格敏感度等稳定属性

**视频推荐**：
- 短期序列捕捉用户当前的观看主题（比如突然对露营感兴趣）
- 长期画像保证推荐的基本盘（比如一直喜欢科技内容）

**新闻资讯**：
- 短期兴趣占主导，因为新闻热点变化快
- 长期兴趣用于区分用户的大类偏好（科技 vs 娱乐）

### 5.2 当前局限性与改进方向

**局限性**：
1. **兴趣迁移处理不够灵活**：用户从学生变成职场人，兴趣发生根本性转变，但长期画像因为历史数据的惯性，更新较慢。
2. **冷启动问题**：新用户没有历史数据，两种建模方式都失效。
3. **正负样本不平衡**：用户点击了什么容易知道，但用户不喜欢什么很难准确获取。

**改进方向**：
1. **引入遗忘机制**：对过于陈旧的行为数据做指数衰减，让模型能更快适应兴趣迁移。
2. **强化学习探索**：让模型主动探索用户的新兴趣，而不是只基于历史数据。
3. **对比学习**：在多兴趣建模时，让同一用户的不同兴趣簇之间保持一定距离，避免它们学成同一个向量。
4. **流式计算架构**：用 Flink 等框架实现准实时更新，每小时聚合一次用户行为，及时更新长期画像。

### 5.3 未来发展趋势

1. **更细粒度的时间建模**：不只是区分短期和长期，而是建立连续的时间感知机制。
2. **多模态兴趣建模**：结合文本、图像、视频等多种模态理解用户兴趣。
3. **因果推断**：区分用户"真正喜欢"和"因为推荐而点击"的行为，建立更准确的兴趣模型。

---

## 六、总结与思考

用户短期兴趣和长期兴趣建模，本质上是让推荐系统学会"既懂你现在的需求，又记得你一直以来的喜好"。短期兴趣像是一个敏锐的雷达，捕捉当下的信号；长期兴趣则像是一个稳定的罗盘，指引推荐的基本方向。

> **思考**：人的兴趣本就是动态变化的，推荐系统追求的"精准"，究竟是让用户永远看到自己喜欢的内容，还是帮助用户发现新的可能性？也许最好的推荐，是在"懂你"和"带你探索"之间找到那个微妙的平衡点。
